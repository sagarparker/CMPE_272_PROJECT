MediaMesh — Azure deployment architecture

Production deployment from compose.deploy.yaml on one Azure VM, with private Azure Blob Storage. Site: https://mediamesh-demo-bf5064f9.swedencentral.cloudapp.azure.com. The numbered arrows are explained in the table below the diagram.

Request flows

Sign-in

  1. The browser is redirected to Keycloak (1 → 2): authorization code + PKCE.
  2. The user enters a password and authenticator code. On first sign-in, Keycloak forces a password change and TOTP enrollment.
  3. The app calls /api/me (1 → 3 → 4). The backend checks signature (JWKS, 5), issuer, audience mediamesh-api and expiry.
  4. The backend maps (issuer, subject) to a user and loads roles from postgres (7). API sessions expire after 30 min idle or 8 h total.

Admin creates an account

  1. The admin submits the form, which calls POST /api/admin/users (1 → 3 → 4).
  2. The backend checks ADMIN. Only the primary admin may create ADMIN accounts.
  3. The backend gets a provisioner token and creates the Keycloak user with a temporary password and the required actions UPDATE_PASSWORD + CONFIGURE_TOTP (5).
  4. The user, role and audit event are saved in postgres (7). The temporary password is returned once.

Upload and indexing

  1. The uploader calls POST /api/assets/initiate. The backend creates the asset (UPLOADING) and a 15-min create-only SAS (7, 13).
  2. The browser PUTs the file straight to Blob Storage (14).
  3. /complete: the backend verifies the stored object, creates a job and sets PROCESSING (13, 7).
  4. ml-worker claims the job (9), downloads the file via managed identity (12), embeds it with CLIP, writes vectors and sets READY.

Search, preview and download

  1. The researcher calls POST /api/search. The backend checks RESEARCHER and finds the eligible READY assets (7).
  2. The backend calls ml-api (6), which embeds the query text and ranks it with pgvector (8). Prometheus records the result (11).
  3. For preview or download, /access-url returns a 60-second read SAS (13). The browser fetches the file directly from Blob Storage (14).

Security boundaries

  • Only ports 80 and 443 are public. SSH is limited to the owner's IP. Postgres, Keycloak, the backend, the ML services and Prometheus have no public ports.
  • Caddy forwards only the sign-in paths to Keycloak. The Keycloak admin console, /actuator and /metrics return 404 publicly.
  • No storage keys exist. Blob access uses the VM managed identity, and browsers get short-lived, narrowly scoped SAS URLs.
  • Secrets live only in runtime/deploy.env (0600) on the VM and in the operator's private copy. The provisioner service account can only manage users.
  • Caddy, Keycloak and nginx images are pinned by digest. Postgres and Prometheus are pinned by tag only.

Release and operations

  • Release: the operator copies a reviewed source snapshot to /opt/mediamesh over SSH. release-manifest.json records file hashes. Images are built on the VM with compose.sh up -d --build. There is no registry or automatic CD.
  • Backups: backup.sh writes pg_dumps of both databases to /opt/mediamesh/backups/. Copy them off-host. Blob versioning and soft delete protect the media files separately.
  • Monitoring: Prometheus is reached through an SSH tunnel. Alerts evaluate but notify no one, because no receiver is configured.
  • Availability: one VM is one failure domain. A reboot or outage stops every service until Docker restarts them.
